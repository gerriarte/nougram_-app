# Arquitectura MVC + Repository/Service

**Última actualización:** 2026-01-25

## Visión General

Este proyecto sigue estrictamente la arquitectura en capas **MVC + Repository/Service** según las reglas definidas en [`.cursorrules/nougram_backend_rules.md`](../../.cursorrules/nougram_backend_rules.md).

## Estructura de Capas

```
┌─────────────┐
│  Endpoint   │  HTTP Request Handling (FastAPI)
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ Controller  │  Validación HTTP, Delegación, Manejo de Errores
└──────┬──────┘
       │
       ▼
┌─────────────┐
│   Service   │  Lógica de Negocio, Validaciones, Orquestación
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ Repository  │  Acceso a Datos, Queries SQLAlchemy, Tenant Scoping
└──────┬──────┘
       │
       ▼
┌─────────────┐
│     ORM     │  SQLAlchemy Models
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Database   │  PostgreSQL
└─────────────┘

       │
       ▼
┌─────────────┐
│    View     │  Transformación de Modelos a Schemas (Pydantic)
└─────────────┘
```

## Principios Fundamentales

### 1. Separación de Responsabilidades
- **Endpoints**: Solo manejan HTTP, delegan a Controllers
- **Controllers**: Validan HTTP, manejan errores, delegan a Services
- **Services**: Contienen toda la lógica de negocio, usan Repositories
- **Repositories**: Solo queries SQLAlchemy, sin lógica de negocio
- **Views**: Transforman Models a Schemas, agregan campos calculados
- **Models**: Solo definición de entidades ORM, sin queries ni lógica

### 2. Flujo de Datos
- **Request**: Endpoint → Controller → Service → Repository → Database
- **Response**: Database → Repository → Service → View → Controller → Endpoint

### 3. Restricciones Estrictas
- ❌ **NO** acceso directo a DB desde Services o Controllers
- ❌ **NO** lógica de negocio en Endpoints o Controllers
- ❌ **NO** queries SQL en Models o Services
- ❌ **NO** transformación de datos en Services
- ✅ **SÍ** usar Repositories para todas las queries
- ✅ **SÍ** usar Views para transformación de datos
- ✅ **SÍ** usar Services para lógica de negocio
